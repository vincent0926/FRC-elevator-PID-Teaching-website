# FRC 9427 前饋與 PID 調參教學網站

FRC 9427 隊員用的調參學習網站。目標是讓你**搞懂**前饋和 PID，最後能自己把機構調好，不是抄數字。

**網址：https://vincent0926.github.io/FRC-elevator-PID-Teaching-website/**

進站先選機構：

- **電梯**：直線上下，位置控制（Motion Magic）
- **單關節手臂**：旋轉，重力跟著 cos θ 變（Arm_Cosine）
- **射球飛輪**：速度控制（VelocityVoltage），連射時轉速撐不撐得住

網站只做計算、模擬、診斷和教學，**不連線機器人、不寫馬達參數**。急停一律用 Driver Station。

## 目前進度：v0.24（電梯、手臂 1F～4F 都完成；射球飛輪 1F 計算、3F 模擬）

## 網站有什麼

網站像一棟樓，從 1F 往上走。每一層標題旁都有「怎麼用這一頁？」，導覽列最上面有完整的「使用說明」。

| 樓層 | 做什麼 | 電梯 | 手臂 | 射球飛輪 |
|---|---|:-:|:-:|:-:|
| 1F 計算參數 | 填機構資料，算出 kS、kG、kV、kA、kP 起始值和 Motion Magic；教學關卡附檢核題 | ✅ | ✅ | ✅ |
| 2F 調參建議 | 匯入 .wpilog（或 3F 送來的模擬資料），照順序找出第一個要修的問題，一次改一個參數 | ✅ | ✅ | — |
| 3F 模擬 | 側視動畫＋圖表，親手拖滑桿調參數，馬上看結果；理想模型和真實模型（飽和、摩擦、電流限制、延遲…）可以逐項開關 | ✅ | ✅ | ✅ |
| 4F 實機資料教學 | 安全須知、AdvantageKit 錄日誌、SysId、常見的坑、兩點法量 kS／kG、期末檢核 | ✅ | ✅ | — |

### 電梯、手臂

- **1F**：參數卡標明哪些能算、哪些一定要量；齒比怎麼選、分享機構連結。最高速度和加速度會扣掉量到的 kS，沒量時標明是不含摩擦的理論上限。
- **2F**：步驟 0 檢查資料，再照「物理限制 → 振盪 → 機構 → kG → kS → kV → kA → kP → kD」找問題。有引導模式和專家模式，附練習用範例日誌。
- **3F**：
  - 教學情境（沒有 kG、kI 補 kG、積分飽和……）、照順序調、挑戰模式。
  - 模型校正、穩健性測試。
  - 達標標準可以自己改。
  - 滑桿可以切成 Phoenix 6 轉數制（rps），數字就是 Slot0Configs、MotionMagicConfigs 要填的值。
- **4F**：單元零（安全）必修，勾完才開放後面的單元。

### 射球飛輪

- **1F 計算參數**：
  - 填馬達、齒比、會轉的質量、輪子半徑、重量分布，算出 kV、kA（rps）、轉動慣量、最高轉速、最快到速時間。
  - **球的另一邊**：固定導板，或是對面也有滾輪一起夾著球（上下夾射）。
  - **轉速 → 球速 → 進不進目標**：仰角、出射高度、目標距離／高度／開口寬度，算出要幾 rps，一鍵設成目標轉速。
  - FRC 2026 預設：**得分物件**下拉選單（FUEL 0.448～0.500 lb）、**套用 2026 HUB 高度**（開口前緣 72 in、開口寬 41.7 in）。
- **3F 模擬**：
  - 從靜止轉到目標，預設連射 50 發（最多 100 發）。
  - 側視動畫畫出每一發的路線，進了是綠點、沒進是紅點。
  - 指標：到速時間、每一發掉多少、多快回來、進了幾發；每一發的明細可以點開看。
  - 最下面給可以直接貼進程式的 Phoenix 6 設定片段。

### 要知道的限制

- 模擬是**教學用的近似模型**，不是馬達韌體的數值重現。
- 達標標準是教學用的，**不是 FRC 官方標準**。
- 2F 的診斷正確率是用本站模擬器產生的**合成資料**測的，還沒有用真實 FRC 日誌驗證。
- 射球的球速和落點不計空氣阻力、假設球不打滑，最後一定要上機射幾發量落點。

還沒做：射球飛輪的 2F、4F；英文版；找新隊員實際試用，看學習成效。

## 從課程連進來（深層連結）

[FRC 9427 程式課程](https://vincent0926.github.io/FRC9427teaching-website/)可以用網址直接開到某個機構、情境或單元：

| 參數 | 值 | 作用 |
|---|---|---|
| `track` | `elevator`、`arm` | 直接進電梯或手臂，不用先選 |
| `scenario` | 3F 情境 id（`src/pages/simulate/simScenarios.ts`、`src/pages/arm/armScenarios.ts`） | 進 3F 時直接載入 |
| `section` | 元素 id，例如 `unit4`、`measure-ks` | 捲到該區塊，`<details>` 自動打開 |
| `from=course&ch=` | 章節編號 0–19 | 顯示「回到課程第幾章」 |

樓層用 hash（`#calc`、`#tune`、`#sim`、`#learn`）。例如：

```
https://vincent0926.github.io/FRC-elevator-PID-Teaching-website/?track=elevator&scenario=noKg&from=course&ch=13#sim
```

參數只接受白名單格式，讀過就從網址拿掉。**改情境 id 或單元 id 時，課程的 `src/data/course.json` 也要一起改**，課程那邊的檢查腳本會比對。

## 開發

需要 Node.js 20 以上（CI 用 22）。

```
npm install
npm run dev        # 開發伺服器 http://localhost:5173
npm test           # Vitest 單元測試（src/core/ 全部要有測試）
npm run typecheck  # tsc
npm run lint       # oxlint
npm run build      # 輸出到 dist/
```

- 技術：React + TypeScript + Vite，PWA（第一次開啟後離線也能用）。
- 部署：推到 `main` 後 GitHub Actions 自動測試、建置、部署到 GitHub Pages，約 1–2 分鐘後網站更新，網頁上方會出現「有新版本」提示。
- 版本只以 `package.json` 為準，這份 README 的「目前進度」要一起改（`test/version.test.ts` 會檢查）。
- 用瀏覽器測試建置結果時，Service Worker 會快取舊版：換新的瀏覽器設定檔或清掉 SW。
